# Mobile Research Sources

| Source | URL | Claim Supported | Status |
|---|---|---|---|
| W3C WCAG 2.2 Understanding | https://www.w3.org/WAI/WCAG22/Understanding/ | Mobile UI quality must account for reflow, focus visibility, focus not obscured, target size, keyboard access, labels, and status messages. | SOURCE INSPECTED |
| MDN Media Queries | https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries | Media queries support responsive layouts, orientation adaptations, larger touch hit areas, and can be paired with container queries for reusable components. | SOURCE INSPECTED |
| web.dev Responsive Web Design Basics | https://web.dev/articles/responsive-web-design-basics | Responsive layouts must fit content inside the viewport and avoid accidental horizontal scrolling. | SOURCE INSPECTED |
| Expo DOM Components | https://docs.expo.dev/guides/dom-components/ | Expo DOM components pass WebView props through `dom`, run as standalone DOM surfaces, and are appropriate for preserving the existing web runtime. | SOURCE INSPECTED |
| Material Adaptive Layout | https://developer.android.com/codelabs/adaptive-material-guidance | Compact, medium, and expanded window classes should guide layout adaptation while still allowing flexible behavior between classes. | SOURCE INSPECTED |
| Apple UI Design Dos and Don'ts | https://developer.apple.com/design/tips/ | Touch layouts should avoid horizontal scrolling, keep content legible, use sufficient contrast and spacing, and target at least 44pt hit areas. | SOURCE INSPECTED |
