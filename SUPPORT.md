# Support

Use GitHub issues for public support:

- Bug reports: include browser, operating system, app commit/version, capture mode, expected result, actual result, and console errors when relevant.
- Feature requests: describe the workflow problem first, then the proposed solution.
- Security reports: follow [SECURITY.md](SECURITY.md) and do not post exploitable details publicly.

The maintained app package lives in `production ready/`; include that path when reporting files or commands.
