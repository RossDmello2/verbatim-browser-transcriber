# Verbatim Application Updates and Feature Requirements

This document outlines all the features, logic updates, and bug fixes requested for the Verbatim application. These specifications serve as a highly precise implementation blueprint.

## 1. Advanced Multilingual & Mixed-Language Processing
**Objective:** Enhance the core transcription engine to dynamically handle single and mixed-language audio files perfectly, acting as both a transcriber and an intelligent contextual translator.

*   **Language Auto-Detection:** The system must accurately detect any spoken language automatically (Hindi, Marathi, English, German, Tamil, Telugu, Bengali, Gujarati, Kannada, Malayalam, etc.).
*   **"Preserve Original Languages" Mode:** 
    *   When an audio file contains multiple languages (e.g., a speaker switching between Hindi and English), the system must explicitly keep the spoken lines in their original language.
    *   Hindi sentences must be transcribed in Hindi (Devanagari script), and English sentences in English. 
    *   It must **not** generalize or force all output into English under this mode.
    *   **Logic Implementation (Hinglish Fix):** Standard models often hallucinate or skip Hindi words when mixed with English. A secondary LLM processing pass (Intelligent mixed-language formatting pass via Groq/Gemini) is required to take the raw Whisper output and fix the code-switching, explicitly formatting Hindi into proper Devanagari while preserving the English context perfectly.
*   **"Translate Everything to English" Mode:**
    *   A dedicated option for users who want the entire transcript, regardless of the source languages, to be translated into pure English.
    *   The translation logic must be heavily context and intent-aware.

## 2. Persistent Audio Player (Transcript Comparison)
**Objective:** Allow users to listen to the uploaded audio while simultaneously reading the generated transcription.

*   **Current Issue:** The `<audio>` player completely disappears or collapses as soon as the user clicks the "Transcribe" button.
*   **Required Logic:**
    *   Extract the `<audio class="file-audio-player">` element from the collapsible file-upload zone.
    *   Relocate the audio player to the Transcript Panel Header (`.tp-header`).
    *   Ensure the player becomes permanently visible and usable during, and indefinitely after, the transcription process is completed.

## 3. High-Fidelity Subtitle & Document Export (.srt, .docx, .txt)
**Objective:** Ensure users can explicitly download their generated transcriptions in standard industry formats directly from the application UI perfectly in sync.

*   **Subtitle Export (.srt):**
    *   Provide a functional "Download as Subtitle (.srt)" button.
    *   **Logic Implementation:** The script must iterate through the timestamped segment array generated by the AI (`state.segments`). It must convert the absolute seconds into strict SubRip Subtitle formatting (`HH:MM:SS,ms --> HH:MM:SS,ms`) and bind it to the respective text strings.
    *   **Sync Requirement:** Timely generation is vital. The timing math must be highly accurate so that when a user uploads a German video, translates it to English, and downloads the `.srt`, it plays in perfect synchronization within external players like VLC without lag or advancement.
*   **Word Document Export (.docx):**
    *   Provide a functional "Download as Word Doc (.docx)" button for clean, un-timestamped reading and editing.
    *   **Logic Implementation:** Parse the raw transcript text and programmatically construct a standard `.docx` (or OOXML `.doc` wrapper) Blob mapping line breaks to XML paragraphs (`<w:p><w:r><w:t>`).
*   **Plain Text Export (.txt):**
    *   Ensure the standard `.txt` text export functions correctly.
*   **Event Binding Fix:** The dropdown buttons must have explicit `type="button"` attributes so they don't trigger fatal page reloads. The click interactions should utilize Document Event Delegation to guarantee the JavaScript catches the click regardless of when the dropdown HTML was rendered into the DOM.

## 5. File Constraints & Support
**Objective:** Support large video files natively to enable the subtitle-extraction workflow.

*   **File Size Limit:** Expand the maximum browser RAM upload ceiling from 200MB to 500MB.
*   **Format Allowlist:** Ensure the application accepts and internally processes mobile and native video formats directly (e.g., `.mov`, `.mkv`, `.avi`, `.amr`, `.3gp`, `video/*`).
